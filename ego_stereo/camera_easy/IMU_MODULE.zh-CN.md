# 统一头环标定工具：IMU 开发验证版

Camera、IMU、Camera–IMU 共用一个程序和同一个安装入口。手机 Ego-Capture 不需要更换。

本版本增加 IMU 静止采集和噪声分析。Camera–IMU 已提供运动数据录制与前置检查，正式求解待时间轴复核。详见 [联合模块](CAMERA_IMU.zh-CN.md)。

## 本次先做 60 秒检查

1. 先结束旧工具的任务，关闭旧启动终端。
2. 下载 headband.zip 到 Linux 的系统“下载”目录。
3. 打开终端，执行：

```bash
cd "$(xdg-user-dir DOWNLOAD)" &&
unzip -oq headband.zip camera.run &&
bash camera.run
```

4. 将头环用 USB 数据线直接连接 Linux，等待左右预览出现。
5. 在“标定类型”选择 **IMU：静止噪声标定**。
6. 保持默认 **先做 60 秒读取检查**，把头环放稳，点击“开始 IMU 录制”。不需要标定板。
7. 等待结束，查看样本数、错误、缺口和输出文件。
8. 将 **imu_small_review.tar.gz** 发给维护者复核。读取失败时也会尽量生成这个小包。

60 秒只用于验证读取、解析、连续性与分析流程，不生成正式噪声标定配置。先通过短检查，再开始长录。

## 自定义时间与静止长录

可选择 2 小时、3 小时，或“自定义时间”，输入数值并选择分钟或小时。例如 30 分钟、1.5 小时、2.5 小时。当前输入范围为 1 分钟至 24 小时，这是软件输入范围，不是标定质量标准。

页面提示：建议静止录制至少 2～3 小时；可按需要调整，较短记录可能不足以估计长期噪声。这是第一轮测试建议，并非官方最低要求。点击开始后直接计入 2 小时采集，没有额外预热等待。头环保持供电、固定放稳；不要触碰、拉线或在桌面敲击。保持电脑唤醒，避免系统休眠。

录制前按目标时长检查磁盘空间，至少 3 GiB，长录需要更多空间。分析内存随样本量增长；本版本尚未完成多小时实机稳定性与资源验证。已有环境自动复用；安装脚本补充绘图依赖，不要求用户另装一个 IMU App。

页面显示经过时间、样本、包数、错误、重复和计数缺口。提前结束或异常退出的数据会保留，状态明确记录，不能当作已完成 2 小时采集。

## 输出文件

| 文件 | 用途 |
|---|---|
| imu_packets.bin | 正式记录阶段通过解析的 252 字节原始包 |
| imu_requests.csv | 记录阶段每次请求的主机起止时间、长度、状态 |
| imu_samples.csv | 原始计数器、原始六轴整数与名义 SI 换算；不伪造逐样本硬件时间 |
| imu_capture.json | 时长、计数、重复、缺口、回跳、异常和换算说明 |
| imu-allan.csv | 各轴 Allan 曲线与有效差分数量 |
| imu-report.pdf | 加速度和陀螺仪 Allan 曲线 |
| imu-results.txt / imu-analysis.json | 分析摘要、采样率估计、斜率区间及待复核问题 |
| imu-candidate.yaml | 满足静止与拟合检查时才生成的实验候选参数 |
| imu_small_review.tar.gz | 报告和摘要小包，不含原始大文件 |

结果按设备放在已有容器 `/data` 对应的宿主数据根目录下 `imu/<设备编号>/<本次目录>/`；页面显示实际路径。

## 已实现及仍待实测

- 使用 Linux UVC XU 读取头环主板 IMU：unit 3、selector 1、GET_CUR；沿用已有 Android 代码的 14×18 字节协议。
- 校验数据头、包内步长、大小端和有符号轴值。计数回绕、重复、缺口分别记录，缺口之间不拼接计算 Allan 差分，不做插值。
- SI 换算暂用原 SDK 名义比例 4096 count/g、16.4 count/(°/s)，并非每台精确比例标定。
- 采样率按主机包时间与计数器拟合估计。该估计不证明硬件时间单位，也不证明与图像曝光同步。
- Allan 白噪声与随机游走只有识别到相应斜率区间才给候选参数；较短记录会给出提示，但不按两小时硬性拒绝候选参数；疑似运动、回跳或拟合不足会明确提示。
- 本机合成数据及软件测试通过；真实 Linux XU 并行读取、2 小时稳定性、噪声结果仍需本次设备验证。
- 本功能是 IMU 噪声分析，不包含六位置加速度比例、轴不正交等完整内参校准。

协议接口参考：[Linux UVC 驱动文档](https://docs.kernel.org/userspace-api/media/drivers/uvcvideo.html)。噪声模型参考：[Kalibr IMU Noise Model](https://github.com/ethz-asl/kalibr/wiki/IMU-Noise-Model)。Kalibr 求解算法未修改。

## 长录计数回绕修复（2026-11-14）

本台 2UQ2 的两小时原始数据表明：字段虽按 u32 读取，实际边界符合 u24 回绕，步长仍为 32。11 次回绕周期约 647.6 秒；旧实现按 32 位解释，造成错误回跳判定，并误拒绝 10 个跨回绕包。另有 3 次数据头不匹配，根因仍待检查。

新读取与分析支持已观察到的边界模式，并保留原始计数值；不将任意回跳解释为回绕。该模式不等于厂商确认的时钟单位，也不证明相机/IMU同步。新采集另存 imu_rejected_packets.bin，并在请求记录中写偏移，便于后续检查。

已有记录可使用 imu_recover.py 从有效原始包重建派生计数和连续片段，输出到新的同级目录；原始文件不修改、不补样本，旧版未保存的拒绝包无法恢复。先检查复算曲线和参数，再决定是否扩大录制。

## 拟合区间修正与复核状态（2026-11-14）

回绕修复后，两小时复算已生成曲线，未识别跳变为零。初版将白噪声搜索限制到 2 秒、随机游走搜索限制为 10 秒之后，且按最长连续片段十分之一限制曲线最长平均时间，可能漏掉真实候选区间。现改为基于曲线峰值、最小值和实测上升/下降支搜索；更长时间尺度按所有完整片段的可用分组差分数量选择。自动时间尺度至少保留 20 个不重叠分组差分，这是工具统计可用性启发规则，不是独立自由度、置信度保证或官方时长门槛。

现有 44.56 秒以内曲线补充拟合后六轴白噪声均有候选，加速度三轴及陀螺 Y 轴有随机游走候选；陀螺 X/Z 的随机游走尚未识别，不生成完整 YAML，也不把数值强填为零或套用其他轴。新版更长时间尺度需要从现有原始数据复算后再评价。


## 20261114-IMU-REVIEW 统一版本

正式轮询仍在每次读取后等待 10ms。0ms 与 5ms 实机短测产生大量 EPIPE，不采用。视频流正常后才能启动 IMU；无预热倒计时。已合入实测 24 位回绕识别、原始无效包保留、按连续段扩展 Allan 时间尺度与按实测下降/上升支路搜索。结果页面新增六轴状态表，逐项显示白噪声、随机游走“候选，待复核”或“未识别”，TXT/JSON 列明缺项。未识别不等于传感器坏；不得填零或借用其他轴。完整候选 YAML 也不等于验收通过。

本机既有两小时数据：六轴白噪声与五轴随机游走出现候选，陀螺仪 Z 随机游走未识别，完整 YAML 尚未生成。工具安装不会自动重算旧数据，也不修改旧记录。暂不要求用户重录两小时。Camera–IMU 在同一入口中提供运动采集与前置检查，正式时间轴和求解仍待验证。


## 实验混合模型权重（旧流程复现）

20261114-IMU-EXPERIMENT 增加独立按钮“生成实验混合模型权重”。仅在本次 IMU 分析完成后可用，使用已有 Allan CSV，0.2～65 秒范围内至少 8 个点、跨度至少 10 倍且差分数至少 100；这些是本工具数值拟合启用条件，不是官方验收阈值。短曲线不足时明确停止，不生成权重。模型为 Allan 方差=N²/τ+P²+K²τ/3，对数空间最小二乘，P 为现象平台项；仅导出 N/K。

输出 imu-experimental.yaml、imu-experimental-fit.json、imu_experimental_review.tar.gz。此次聚合只取全记录曲线同类三轴最大值，没有四分段数据，不能声称复刻旧全记录及四分段聚合，也不是置信上界。模型 K 不等于已独立观测到 +0.5 斜率。原 imu-analysis.json、逐轴状态、正式候选 YAML 条件均保持，实验文件绝不设置质量通过或硬件同步通过。不得把本台设备参数当作其他头环默认值。Camera–IMU 正式求解仍待时间轴和动态残差复核。
