# Camera–IMU：录制、计算和验证顺序

## 当前目标与录制按钮修复（20261115-RECORD-FIX）

当前阶段验证 **Camera、IMU、Camera–IMU 三条流程能否采集、计算并生成结果文件**，
暂不把高精度重复性、跨装配外参一致或硬件同步证明设为流程跑通的前置条件。
主板撕胶重新粘接可能改变其与相机的相对位置，旧装配与新装配的外参不要求相同。
单次联合录制期间保持主板和相机的相对位置固定即可。

旧版界面在两份 YAML 未齐时直接禁用第三步录制按钮，同时显示“准备就绪”，这是按钮条件设计问题。
现改为：

| 当前情况 | 按钮与行为 |
|---|---|
| 设备就绪，参数未齐 | “开始联合录制”可点；录完保留原始数据和目录，之后补参数计算 |
| 设备就绪，Camera 与 IMU 参数齐全 | “开始录制并计算”；录完自动整理 BAG 并计算 |
| 已有联合录制，准备直接计算 | 需要选好数据并补齐两份参数，才启用“开始计算” |
| 设备未就绪、任务运行中或导入未完成 | 明确显示/提示相应原因，避免无解释置灰 |

缺参数录完后：选择“已有录制，直接计算” → 选择刚才录制 → 拖入 `camera-camchain.yaml` 和 IMU 噪声 YAML → 开始计算。
可以复用已经生成的对应相机参数与当前 IMU 实验权重，不需要因按钮修复而重录两小时 IMU。
录制完成不等于已经完成计算；两者分别显示状态、保存路径和实际生成的文件。

Camera、IMU 的独立计算流程不变。可选的“联合标定结果复核”继续默认折叠，
当前不要求额外运行协方差、运动诊断或独立精度研究来使用录制和计算功能。
方法跑通与最终参数精度是不同结论；当前实验参数说明保留在报告中，不用它阻止先采集。

## 本地文件与文件夹导入（20261114-LOCAL-IMPORT）

选择“已有录制，直接计算”后，优先显示一个拖入区域和两个按钮：
**选择本地文件**、**选择录制文件夹**。可以从文件管理器拖入文件或整个录制文件夹；
旧的自动发现列表放在“或从已发现的本机录制中选择”折叠项中，不再要求先把文件移到固定目录。

| 模块 | 选择什么 | 仍需确认什么 |
|---|---|---|
| Camera | 一个 ROS1 相机 `.bag`；可同时选择对应 `aprilgrid.yaml`，也可选择录制文件夹 | 板配置缺失时，在页面填写实测行列、标签边长和间距 |
| IMU | 选齐 `imu_samples.csv`、`imu_capture.json`，或选择本工具的完整静止录制文件夹 | 当前支持本工具 CSV 列结构及连续性/时间元数据，不把未知格式或任意 IMU BAG 当作兼容数据 |
| Camera–IMU | 一个联合 `.bag`，或完整联合原始录制文件夹（图像、清单、IMU CSV、时钟及采集元数据） | 在原有两个参数框另行拖入 `camera-camchain.yaml` 和 IMU 噪声 YAML |

使用顺序：选择模块 → 已有录制直接计算 → 拖入/选择数据 → 等待导入并检查 → 点击开始计算。
页面显示当前文件和百分比；可取消导入。导入成功后自动选中，不需要再次在列表里查找。

大文件按 8 MiB 分段保存到当前本机数据根目录的 `imports/<模块>/<随机目录>/`，不传到互联网，
不一次加载整个 BAG 到浏览器内存。导入及后续计算需要副本空间；原文件不改动。导入期间保持
页面和启动终端打开。取消会删除本次尚未完成的导入副本；已经导入成功的数据与原始文件保留。
一次最多 20000 个文件、总计 100 GiB；隐藏文件忽略。若选错上级目录导致多段 BAG 混在一起，
应重新选择单个 BAG 或单次录制文件夹。不会自动猜选多个 BAG 中的某一个。

相机 BAG 需要 `/cam0/image_raw`、`/cam1/image_raw` 的 `sensor_msgs/Image`；联合 BAG 另需
`/imu0` 的 `sensor_msgs/Imu`（按 ROS SI 单位 m/s²、rad/s）。完整读取检查在开始计算后进行，
包括消息类型、图像长度、非有限 IMU 值、各话题时间递增及联合时间重叠。不会自动改话题或修补回跳。
导入的联合 BAG 使用其原有消息时间；不把格式检查通过描述成曝光同步或硬件时间已验证。

若随数据提供 `aprilgrid.yaml`，计算时复用该配置；未提供时，使用**点击开始计算时**页面上的实测尺寸，
不会在导入文件时悄悄固定默认的 88 / 26.4 mm。PDF、TXT 仍是输出报告，不是所需的计算输入。
额外的联合标定结果复核继续默认折叠，不影响正常三步操作。

本模块在“头环标定工具”中，与 Camera、IMU 共用安装入口。

## 简化主流程：20261114-COMPUTE-FLOW

选择第三步 Camera–IMU，只需确认第一步的相机参数 YAML 与第二步的 IMU 噪声参数 YAML。
本 App 刚生成或上次明确使用的同设备参数可自动带入，并显示文件名供核对；文件丢失或内容
变化则不自动复用，切换设备会清除当前选择。首次使用仍可手动拖入。

实时预览、开始／结束按钮、动作提示和进度位于同一个固定区域。点击“开始录制并计算”，
录制到时或主动结束后，自动生成并读回核对 BAG，再启动实验联合求解。无需手动选择刚录制
的目录。计算结束显示保存路径和“打开结果文件夹”；报告和日志默认折叠。
两份参数未齐仍可先录制；只有联合计算需要补齐两份参数。

标定板 YAML 由页面确认的实测尺寸生成，不要求再拖入。当前第三步仍明确标注实验时间映射
与结果需复核，不伪造最终验收通过。

## 已录完数据：直接计算并查看实时过程

界面版本：20261115-RECORD-FIX。

1. 选择 Camera、IMU 或 Camera–IMU 模块。
2. “操作”选择“已有录制，直接计算”，选择本机保存的对应录制。
3. Camera 和 IMU 无需导入其他模块的结果；第三步才需要拖入下表的两个参数。
4. 点击预览旁“开始计算”。下方实时过程像终端一样滚动显示实际输出；某些步骤无新输出时请等待，不能把日志暂时安静当作失败。
5. 完成后显示 YAML、PDF、TXT 等实际生成的文件，以及结果保存目录和“打开结果文件夹”。

| 模块 | 计算输入 | 是否需要其他步骤的结果 |
|---|---|---|
| Camera | 本工具录制目录中的 camera.bag；优先复用原录制 aprilgrid.yaml，缺失时使用页面实测板尺寸 | 不需要 IMU 结果 |
| IMU | 本工具保存的 imu_samples.csv、imu_capture.json（含单位换算后的六轴值及连续性/时间信息） | 不需要 Camera 结果或标定板 |
| Camera–IMU | 联合运动录制，加第一步 camera-camchain.yaml、第二步 imu-candidate.yaml 或明确标注实验用途的 imu-experimental.yaml | 需要 Camera 与 IMU 参数 |

只有 BAG 仍不足以表达 Camera 标定板的物理尺寸；这里直接复用工具保存的配置，不让用户反复找文件。
当前 IMU 重算读取的是本工具保存的静止录制格式，**不是任意 IMU BAG 导入器**。
快捷列表扫描当前数据根目录；列表以外的数据可在上方拖入或使用本地文件/文件夹选择器导入。
Camera 使用 /cam0/image_raw、/cam1/image_raw 的原始图像消息；不自动改写话题或猜测设备。

重算创建新的计算目录，保留原 BAG、CSV 和旧结果。Camera 先读回检查已有 BAG 的图像内容结构、时间记录及哈希，
再使用 Kalibr 求解；这不等于已经与最初的图像文件逐像素复核。IMU 按连续片段做 Allan 分析，
缺少可靠噪声项时保留曲线/PDF/TXT，并明确未生成完整候选 YAML，不补零、不虚报成功。

正常现场录制仍支持“录制结束后自动计算”，不用手动整理文件。Camera–IMU 第三步计算才需要两个 YAML；
PDF、TXT 是报告，无需作为输入拖入。当前联合计算使用实验时间映射和噪声权重，结果需结合报告判断。

“可选：联合标定结果复核”只在第三步底部，默认折叠。它是使用另一段独立数据检查已算出参数的一致性，
不是以上 Camera、IMU、Camera–IMU 正常计算的前置步骤；不需要时可以一直忽略。

## 第三步到底拖什么文件

| 区域 | 需要的文件 | 不需要的文件 |
|---|---|---|
| 第一步 Camera | 不需要先导入参数；连接头环录制 | 不需要 IMU YAML |
| 第二步 IMU | 不需要先导入参数；保持头环静止录制 | 不需要 Camera YAML 或标定板 |
| 第三步 Camera–IMU 左侧 | 第一步输出的 `camera-camchain.yaml` | PDF、TXT 只是报告，不作为计算输入 |
| 第三步 Camera–IMU 右侧 | 第二步输出的 `imu-candidate.yaml`，或明确标注实验用途的 `imu-experimental.yaml` | `imu-analysis.json`、Allan CSV 不是噪声 YAML |

本工具直接录制时会自动准备 BAG 和标定板配置，不需要用户再拖入 BAG。BAG 保存的是
观测数据；联合求解还需要相机模型参数、IMU 噪声权重和板尺寸，只有 BAG 并不够。
IMU 尚未生成完整候选 YAML 时，不要把报告改名成 YAML；当前实验文件是单独生成的权重。

## 可选：联合标定结果复核（一般无需展开）

此功能仅在第三步页面底部提供，默认折叠；Camera、IMU 页面不显示。切换模块后重新收起。
正常录制、计算不需要展开，也不要求先复核才能采集。

用途：用另一段独立运动数据，检查已计算参数的一致性。不是重新计算一套外参。
需要时展开该区域，选择本机已有的独立联合录制或已准备 BAG，再拖入：

1. 第三步输出的 `joint-camchain-imucam.yaml`；旧版本可用 `camera_imu-camchain-imucam.yaml`。
2. 计算该结果时使用的同一份 IMU 噪声 YAML，例如当前的 `imu-experimental.yaml`。

点击“开始验证”后，固定相机内参、双目基线、相机–IMU 外参和时间偏移，只拟合该段的轨迹、
重力方向及 IMU 偏置并报告残差。完成后显示结果目录。不要用求解参数的原录制冒充独立验证。
此条件检查不能证明硬件同步或替代全部质量判断，当前实验时间映射和噪声权重仍需复核。

本机参数列表、高级的已有数据重新计算均放在更深层折叠项内；只想按三步操作的用户可以忽略。
大 BAG 在本机数据目录处理；本地文件导入通过浏览器分段传给本机 App，不上传互联网。
原始采集与已有数据任务互斥；更新前需结束任务并退出旧启动终端。

## 1. 三项一定要按顺序录吗

| 步骤 | 能否先录 | 计算前需要什么 |
|---|---|---|
| Camera | 可以独立录制 | 相机图像、正确的标定板配置 |
| IMU | 可以独立录制，与 Camera 顺序可互换 | 静止 IMU 数据、单位和采样时间依据 |
| Camera–IMU | 可以先录运动数据，之后补参数 | 同一套头环的相机参数、IMU 噪声参数、板配置、图像与 IMU 联合运动数据及可用时间轴 |

新用户推荐 **Camera → IMU → Camera–IMU**；需要进一步检查时，再做可选的独立数据复核，便于逐项发现问题。Camera 与 IMU 并不互相依赖，不用为了调整顺序重录。

采集可以先做；联合计算不能省略相机与 IMU 参数。已有匹配、可靠且经过复核的参数也可以使用，不要求每次重新计算前两项。参数必须对应同一套传感器、分辨率、镜头设置和固定结构；设备结构变化后需要重新评估相关标定。

IMU 噪声 YAML 与完整 IMU 内参是两回事。官方要求应用 IMU 比例、轴不正交等修正，或使用能估计相应参数的 IMU 模型。本开发版正式求解封装使用 calibrated 模型，必须先有对应修正依据，不能仅凭噪声 YAML 声称满足此条件。

## 2. 当前版本能做什么

- 已接入联合运动数据录制，同时保存左右灰度图像、IMU 原始包、六轴数据、主机时间记录和本次板配置。
- 图像按约 10 对/秒保存；不把它描述成已验证的 20 Hz 采集。实际频率写入检查报告。
- 可以选择 Camera 参数 YAML 和 IMU 噪声 YAML，程序检查格式、分辨率、话题、有限数值与外参格式，并保存本次输入和 SHA256。
- 缺少参数仍允许先录制，检查结果会逐项列出缺失内容。
- 当前图像使用主机完整帧读取时间，IMU 保留包请求时间和原始计数器。主机时间区间有重叠，不等于逐样本时间和图像曝光已经对齐。
- 因此此版不会自动从这些未复核数据生成正式联合 BAG 或启动正式求解。正式时间复核门禁保持；已有数据区域可明确选择实验时间映射进行试算和条件一致性检查。
- 官方 Kalibr 求解调用、输入检查及输出检查封装已编写；缺少 BAG、相机/IMU YAML、板配置、匹配的时间复核记录或 IMU 内参修正依据时，会拒绝正式求解。
- “联合采集完成”只表示本次原始数据已保存和初步检查，不表示已经有联合外参或通过质量验证。

本次开发不修改正在运行的那一份程序，也不访问你的头环。等长录结束并保存后，再退出旧工具安装开发包。

## 4. 第一次录制联合运动数据

1. 用数据线将完整固定的头环连接 Linux，等待左右连续预览。
2. 选择 **Camera–IMU：联合数据采集与前置检查**。
3. 核对设备编号、板行列和实测标签边长/间隔。准备光照均匀、平整且固定不动的 AprilGrid。
4. 已有参数时，选择 Camera 输出的 `camera-camchain.yaml` 和经复核的 IMU 噪声配置。还没有参数时可以留空，先保存运动数据。
5. 默认选 90 秒。把板固定住，人拿着整套头环移动，保持相机与主板 IMU 之间的固定关系。
6. 点击“录制联合标定数据”。先短暂静止，随后做左右摇头、上下点头、左右侧倾，变化一些速度，再加少量前后/左右平移，最后逐渐恢复静止。
7. 尽量让左右相机持续看清板和角点，增加不同位置、距离和角度；避免撞击、拖影、反光以及拿起放下时突然抖动。
8. 结束后看“前置检查”，将 `camera_imu_small_review.tar.gz` 上传复核。

## 6. 正式联合计算的输入与输出

正式计算前需准备并核对：

| 条件 | 要求 |
|---|---|
| Camera 参数 | 双目内参与外参、分辨率、左右话题顺序匹配，并检查相机标定质量 |
| IMU 参数 | 正值、有限、单位正确的噪声密度和随机游走参数、话题与采样率；另确认内参修正依据 |
| 板配置 | 与运动数据中的实体板匹配，尺寸实测 |
| 联合 BAG | 同一段运动的左右图像和 IMU，单位与消息格式正确 |
| 时间复核 | 逐样本时间递增、缺口和抖动有据可查，图像与 IMU 时基可用；复核记录与 BAG、配置校验和匹配 |

维护者求解封装使用：

```bash
rosrun kalibr kalibr_calibrate_imu_camera \
  --bag camera_imu.bag \
  --cam input-camera.yaml \
  --imu input-imu.yaml \
  --target aprilgrid.yaml \
  --imu-models calibrated \
  --dont-show-report
```

这条命令只说明正式求解接口；当前采集开发包不会绕过前置检查自动执行它。

| 求解输出 | 用途 |
|---|---|
| camera_imu-camchain-imucam.yaml | 相机相对 IMU 的变换和时间偏移 |
| camera_imu-report-imucam.pdf | 联合残差、时间间隔等图表 |
| camera_imu-results-imucam.txt | 官方求解结果摘要 |
| joint_calculation.json、joint_calibration.log | 输入核查、求解状态、运行时间和日志 |

`T_cam_imu` 把 IMU 坐标变换到相机坐标；`timeshift_cam_imu` 单位为秒，官方定义为 `t_imu = t_cam + shift`。

## 7. 怎么算验证完成

1. Camera：检查重投影误差、全画面覆盖、基线与实物一致性。
2. IMU：检查单位、计数连续性、静止条件、曲线和参数拟合是否有依据；时长只是参考。
3. Camera–IMU：检查图像/IMU 时间间隔、运动覆盖、重投影和惯性残差、外参合理性。
4. 再录一段独立运动数据，检查参数适用性或重复标定的稳定性。不能只在训练数据上计算一次就宣称全套完成。

Camera、IMU 的结果是联合计算的前提之一，但不是联合结果通过的充分条件。即使三类 YAML/PDF/TXT 都生成，仍需完成上述复核。

## Camera–IMU 的安装前提：主板必须与摄像头刚性固定

带 IMU 的主板必须牢固固定在头环结构上，与两个摄像头保持恒定的位置和朝向。不能让主板悬空、仅靠排线支撑、手托或在壳内滑动；数据线应有余量，不能拉动主板。开始前轻轻移动整套头环，检查主板和摄像头没有相对晃动。联合录制时固定标定板，移动已经固定成一体的头环。软件无法仅凭图像检出或求解退出码证明安装牢固。

主板重新移动或转向后，旧 Camera–IMU 外参不再对应新安装，应固定后重录联合数据。若两个摄像头和镜头的相对位置、焦距等没有改变，主板移动本身不要求重做 Camera 标定；若摄像头也松动则需重做。静态 IMU 噪声记录是否重录取决于录制时主板是否真正静止，不能因这次主板掉落就自动宣布先前两小时数据失效。
