# 头环标定工具：统一入口（开发验证版）

## 当前目标与录制按钮修复（20261115-RECORD-FIX）

当前阶段验证 **Camera、IMU、Camera–IMU 三条流程能否采集、计算并生成结果文件**，
暂不把高精度重复性、跨装配外参一致或硬件同步证明设为流程跑通的前置条件。
主板撕胶重新粘接可能改变其与相机的相对位置，旧装配与新装配的外参不要求相同。
单次联合录制期间保持主板和相机的相对位置固定即可。

旧版界面在两份 YAML 未齐时直接禁用第三步录制按钮，同时显示“准备就绪”，这是按钮条件设计问题。
现改为：

| 当前情况 | 按钮与行为 |
|---|---|
| 设备就绪，参数未齐 | “开始联合录制”可点；录完保留原始数据和目录，之后补参数计算 |
| 设备就绪，Camera 与 IMU 参数齐全 | “开始录制并计算”；录完自动整理 BAG 并计算 |
| 已有联合录制，准备直接计算 | 需要选好数据并补齐两份参数，才启用“开始计算” |
| 设备未就绪、任务运行中或导入未完成 | 明确显示/提示相应原因，避免无解释置灰 |

缺参数录完后：选择“已有录制，直接计算” → 选择刚才录制 → 拖入 `camera-camchain.yaml` 和 IMU 噪声 YAML → 开始计算。
可以复用已经生成的对应相机参数与当前 IMU 实验权重，不需要因按钮修复而重录两小时 IMU。
录制完成不等于已经完成计算；两者分别显示状态、保存路径和实际生成的文件。

Camera、IMU 的独立计算流程不变。可选的“联合标定结果复核”继续默认折叠，
当前不要求额外运行协方差、运动诊断或独立精度研究来使用录制和计算功能。
方法跑通与最终参数精度是不同结论；当前实验参数说明保留在报告中，不用它阻止先采集。

## 本地文件与文件夹导入（20261114-LOCAL-IMPORT）

选择“已有录制，直接计算”后，优先显示一个拖入区域和两个按钮：
**选择本地文件**、**选择录制文件夹**。可以从文件管理器拖入文件或整个录制文件夹；
旧的自动发现列表放在“或从已发现的本机录制中选择”折叠项中，不再要求先把文件移到固定目录。

| 模块 | 选择什么 | 仍需确认什么 |
|---|---|---|
| Camera | 一个 ROS1 相机 `.bag`；可同时选择对应 `aprilgrid.yaml`，也可选择录制文件夹 | 板配置缺失时，在页面填写实测行列、标签边长和间距 |
| IMU | 选齐 `imu_samples.csv`、`imu_capture.json`，或选择本工具的完整静止录制文件夹 | 当前支持本工具 CSV 列结构及连续性/时间元数据，不把未知格式或任意 IMU BAG 当作兼容数据 |
| Camera–IMU | 一个联合 `.bag`，或完整联合原始录制文件夹（图像、清单、IMU CSV、时钟及采集元数据） | 在原有两个参数框另行拖入 `camera-camchain.yaml` 和 IMU 噪声 YAML |

使用顺序：选择模块 → 已有录制直接计算 → 拖入/选择数据 → 等待导入并检查 → 点击开始计算。
页面显示当前文件和百分比；可取消导入。导入成功后自动选中，不需要再次在列表里查找。

大文件按 8 MiB 分段保存到当前本机数据根目录的 `imports/<模块>/<随机目录>/`，不传到互联网，
不一次加载整个 BAG 到浏览器内存。导入及后续计算需要副本空间；原文件不改动。导入期间保持
页面和启动终端打开。取消会删除本次尚未完成的导入副本；已经导入成功的数据与原始文件保留。
一次最多 20000 个文件、总计 100 GiB；隐藏文件忽略。若选错上级目录导致多段 BAG 混在一起，
应重新选择单个 BAG 或单次录制文件夹。不会自动猜选多个 BAG 中的某一个。

相机 BAG 需要 `/cam0/image_raw`、`/cam1/image_raw` 的 `sensor_msgs/Image`；联合 BAG 另需
`/imu0` 的 `sensor_msgs/Imu`（按 ROS SI 单位 m/s²、rad/s）。完整读取检查在开始计算后进行，
包括消息类型、图像长度、非有限 IMU 值、各话题时间递增及联合时间重叠。不会自动改话题或修补回跳。
导入的联合 BAG 使用其原有消息时间；不把格式检查通过描述成曝光同步或硬件时间已验证。

若随数据提供 `aprilgrid.yaml`，计算时复用该配置；未提供时，使用**点击开始计算时**页面上的实测尺寸，
不会在导入文件时悄悄固定默认的 88 / 26.4 mm。PDF、TXT 仍是输出报告，不是所需的计算输入。
额外的联合标定结果复核继续默认折叠，不影响正常三步操作。

Camera、IMU、Camera–IMU 共用同一 App。选择模块后按页面录制、计算，结束显示结果路径。IMU 使用步骤见 [IMU 模块](IMU_MODULE.zh-CN.md)，第三步所需文件及可选复核见 [Camera–IMU 操作说明](CAMERA_IMU.zh-CN.md)。当前联合求解使用实验时间映射和噪声权重，结果需结合报告判断。

## 已录完数据：直接计算并查看实时过程

界面版本：20261115-RECORD-FIX。

1. 选择 Camera、IMU 或 Camera–IMU 模块。
2. “操作”选择“已有录制，直接计算”，选择本机保存的对应录制。
3. Camera 和 IMU 无需导入其他模块的结果；第三步才需要拖入下表的两个参数。
4. 点击预览旁“开始计算”。下方实时过程像终端一样滚动显示实际输出；某些步骤无新输出时请等待，不能把日志暂时安静当作失败。
5. 完成后显示 YAML、PDF、TXT 等实际生成的文件，以及结果保存目录和“打开结果文件夹”。

| 模块 | 计算输入 | 是否需要其他步骤的结果 |
|---|---|---|
| Camera | 本工具录制目录中的 camera.bag；优先复用原录制 aprilgrid.yaml，缺失时使用页面实测板尺寸 | 不需要 IMU 结果 |
| IMU | 本工具保存的 imu_samples.csv、imu_capture.json（含单位换算后的六轴值及连续性/时间信息） | 不需要 Camera 结果或标定板 |
| Camera–IMU | 联合运动录制，加第一步 camera-camchain.yaml、第二步 imu-candidate.yaml 或明确标注实验用途的 imu-experimental.yaml | 需要 Camera 与 IMU 参数 |

只有 BAG 仍不足以表达 Camera 标定板的物理尺寸；这里直接复用工具保存的配置，不让用户反复找文件。
当前 IMU 重算读取的是本工具保存的静止录制格式，**不是任意 IMU BAG 导入器**。
快捷列表扫描当前数据根目录；列表以外的数据可在上方拖入或使用本地文件/文件夹选择器导入。
Camera 使用 /cam0/image_raw、/cam1/image_raw 的原始图像消息；不自动改写话题或猜测设备。

重算创建新的计算目录，保留原 BAG、CSV 和旧结果。Camera 先读回检查已有 BAG 的图像内容结构、时间记录及哈希，
再使用 Kalibr 求解；这不等于已经与最初的图像文件逐像素复核。IMU 按连续片段做 Allan 分析，
缺少可靠噪声项时保留曲线/PDF/TXT，并明确未生成完整候选 YAML，不补零、不虚报成功。

正常现场录制仍支持“录制结束后自动计算”，不用手动整理文件。Camera–IMU 第三步计算才需要两个 YAML；
PDF、TXT 是报告，无需作为输入拖入。当前联合计算使用实验时间映射和噪声权重，结果需结合报告判断。

“可选：联合标定结果复核”只在第三步底部，默认折叠。它是使用另一段独立数据检查已算出参数的一致性，
不是以上 Camera、IMU、Camera–IMU 正常计算的前置步骤；不需要时可以一直忽略。

## Camera 模块（彩色预览）

本入口的 Camera 模块处理 2UQ2 的相机标定。头环直接接 Linux 电脑，不经过手机；固定头环，按页面提示移动标定板。60 秒采集结束后自动生成并读回核对 BAG，再运行 Kalibr 的 ds-none 双目模型。

## 需要什么

| 项目 | 要求 |
|---|---|
| 系统 | 首版安装脚本面向 Ubuntu 22.04 / 24.04 桌面版、x86_64 |
| 硬件 | 完整固定的 2UQ2 双目头环、支持数据的 USB 线、平整的 AprilGrid 标定板 |
| 主机软件 | Python3、OpenCV、NumPy、PyYAML、FFmpeg、V4L2 工具、Docker、浏览器；安装脚本统一安装缺少的依赖 |
| 标定环境 | Kalibr / ROS Noetic 在 Docker 内运行，宿主机不用安装 ROS、catkin 或单独编译 Kalibr |
| 磁盘 | 默认 60 秒约保存 240 对 1920×1080 灰度图，图像和 BAG 通常占数 GiB；工具在采集前检查空间 |
| 计算硬件 | 此相机流程使用 CPU，不要求 CUDA 或独立显卡；运行时间取决于观测量、CPU 和环境 |

## 下载和安装

完整下载、安装及录屏步骤见 [安装教程](INSTALL_SIMPLE.zh-CN.md)。普通用户不需要登录 GitHub、不需要克隆仓库。

v1.2 小包包含当前程序，v1 已发布的 9 个分卷提供 Kalibr 环境。新电脑使用下载脚本自动完成两者的下载、校验和安装；已有 Kalibr 的电脑只安装 v1.2 小包。

从源码安装时，在本目录运行 `bash install.sh`；完成后运行 `bash start.sh`。首次需要联网和管理员密码，工具使用系统 Python，不使用 Conda 环境。

## 每次使用

1. 头环固定好，用 USB 数据线直接接 Linux 电脑；手机端不再占用这根线。
2. 打开应用菜单的“**双目相机标定**”，或执行 `bash start.sh`。
3. 等待浏览器里左右连续画面出现。检查两眼均清晰、没有黑屏。
4. 填写设备编号，核对板行列数、**实测黑色标签外框边长和标签之间空白间距（mm）**。默认 6×6、88 / 26.4 mm 是示例，不是所有板通用。
5. 点击“**开始相机标定**”，按页面提示让板覆盖中心、四角、边缘，做倾斜和远近变化；头环不要动。尽量让两个镜头都能看到板，避免反光、拖影和弯曲。
6. 默认采集 60 秒，然后自动整理图像、生成相机 BAG、读回核对，再计算 DS 双目内参与外参。也可选 90 / 120 秒；提前结束按钮只在至少保存 40 对后可用，40 对不是标定质量通过条件。
7. 结束后页面提供 PDF、YAML、TXT 和小检查包的链接。查看 PDF，确认重投影误差和观测覆盖，并核对基线是否符合实物。

新 Ubuntu 22.04 已完成实际采集和 Kalibr 计算，170 对输入、74 对最终使用，YAML/PDF/TXT 已生成。该次计算经过手动修复后重跑；v1.2 已合并修复，彩色实时预览和网页完整流程仍待实机复测。源码没有修改 Kalibr 求解算法。

## 结果目录

旧工作站复用容器 `/data` 对应宿主目录。新建容器默认放在 `~/EgoStereoIMU/calibration_data/`。每次创建独立目录，页面会显示实际路径。

| 文件或目录 | 内容 |
|---|---|
| `images/cam0/`、`images/cam1/` | 原尺寸 1920×1080 的无损灰度 PGM，左右由同一帧拆分 |
| `camera_manifest.json` | 选中图像、整数纳秒时间、文件校验和 |
| `camera.bag` | 左右 `/cam0/image_raw`、`/cam1/image_raw`，不包含 IMU |
| `bag_verification.json` | 全部图像像素、时间和消息数量的读回核对结果 |
| `aprilgrid.yaml` | 用本次实测尺寸生成的标定板配置 |
| `camera-camchain.yaml` | 本次双目内参与外参 |
| `camera-report-cam.pdf` | Kalibr 报告 |
| `camera-results-cam.txt` | 参数和残差文本 |
| `calculation.json` | 状态、镜像 ID、输入校验和、real/user/sys 时间、输出检查 |
| `hardware.json`、`run_status.json`、日志 | 设备、环境、阶段、失败原因和命令记录 |
| `camera_easy_small_review.tar.gz` | 报告、配置与日志，不含大图像和 BAG；复核只需发这个包 |

预览为 10 FPS 的连续 MJPEG 流，FFmpeg 将原 MJPEG 解码为 BGR 彩色图像供预览；仅在保存标定帧时转换为灰度；用于标定的图像按约 4 Hz 保存。只对预览缩小，标定图像不缩放、不矫正、不锐化。相机标定使用的时间是主机完整帧读取时间，不能拿此时间轴直接做 camera_imu。

“结果已生成”表示程序和文件检查完成，**不自动宣称标定质量通过**。没有检测目标、角点不足、优化失败、NaN、缺少输出时会显示失败，保留本次数据。输入流停止有超时，页面不会因拔线一直等待一个不完整帧。

## 关闭与问题处理

浏览器关闭后，启动终端里的任务仍继续。需要停止工具可在该终端按 Ctrl+C；只向本次标定进程组发终止信号，不关闭整个容器。

没有视频：确认插在 Linux 上、只有一套 2UQ2、没有其他应用占用设备，重新插拔或重新登录使权限生效。

提示缺少镜像：先运行 `install.sh`，选择已下载的 Kalibr 镜像。现有 `/data` 挂载不可写时会明确报出实际目录，不自动 chmod 全盘。

DS 初始化或优化失败：先看本次日志和图案是否清晰、尺寸是否正确、姿态是否丰富。不自动切模型、塞焦距或修改 Kalibr 算法来掩盖失败。

## 新机容器启动修复

镜像自带 ENTRYPOINT 时，新建容器必须显式覆盖为 /bin/sleep，不能只添加 CMD sleep infinity。当前源码已修复，并检查启动状态。旧 camera-easy-v1 分卷内容未变，发生该故障的新机需使用 camera-fix.zip 继续安装；镜像和数据可复用。真实新机验证仍待完成。

第二版修复补充：镜像内 root 用户的 rosdep 缓存离线复制给运行用户；环境检查改为实际模块导入、DoubleSphere 模型检查及包定位，不把 Kalibr --help 返回 2 误判为环境缺失。camera-fix-v2.zip 可兼容原始安装和第一版修复。
