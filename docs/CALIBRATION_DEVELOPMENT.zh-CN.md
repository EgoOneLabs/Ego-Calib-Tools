# 头环标定工具：功能、验证与开源记录

更新：2026-11-14。范围：2UQ2 双目头环的 Camera、IMU、Camera–IMU，统一在 Linux 标定工具内提供。Android Ego-Capture 负责日常采集，Linux 工具负责标定。本文随功能、测试与发布一起更新。

## 1. 产品约定

- 一个安装包、一个应用入口，选择三个标定模块，不要求分别安装三个 App。
- 共用设备编号、设备连接、彩色连续预览、保存目录、日志、结果查看与小文件检查包。
- 普通用户按教程下载、安装、连接、采集、查看结果，不需要 GitHub 账号或编译源码。
- 发布完整源码、安装入口、环境说明、标定操作、输出格式、验证方法和已知问题。
- 每项功能区分代码完成、软件测试、设备实测和结果复核；公开说明实际完成范围。

## 4. 时长与判定依据的纠正

“两小时最低”是本工具早期设置的试录门槛，不是 Kalibr 官方最低时长，也不能保证参数可靠。Kalibr 官方 IMU Noise Model 文档建议使用约 15–24 小时静止记录进行 Allan 分析。

- 短录可检查读取、换算、连续性并尝试估计白噪声。
- 长录用于观察慢变化噪声；判断应结合连续片段、有效统计量、曲线与拟合区间。
- 已新增自定义时间，支持分钟或小时，输入范围 1 分钟至 24 小时，保留 60 秒、2 小时、3 小时快捷选项。
- 页面建议至少静止录制 2～3 小时，作为第一轮长录建议，不设为强制阈值。取消 7200 秒及最长片段 600 秒对候选 YAML 的硬门槛，按静止检查和实际噪声拟合区间决定是否提供候选；提前结束和短录在报告中单独提示。
- 自动预热已取消。官方静态噪声模型假设静止和恒温；取消软件等待不代表温度变化不影响结果。

依据：[Kalibr IMU Noise Model](https://github.com/ethz-asl/kalibr/wiki/IMU-Noise-Model)。

## 6. 时间和参数说明

- IMU 名义换算：4096 count/g、16.4 count/(°/s)，来源于既有 SDK 配置，不是每台精确比例标定。
- 原始计数器与主机请求区间均保留；拟合采样率是经验估计，不等于厂商确认的逐样本硬件时间。
- Camera 当前使用主机完整帧读取时间，不等于曝光时刻；Camera–IMU 必须另行核对两者时间关系。
- Allan 噪声分析不包含加速度六位置比例、轴不正交等完整 IMU 内参校准。
- 设备几何、轴向、时间偏移和配置关联须在联合标定与独立数据验证时明确记录。

## Camera–IMU 的安装前提：主板必须与摄像头刚性固定

带 IMU 的主板必须牢固固定在头环结构上，与两个摄像头保持恒定的位置和朝向。不能让主板悬空、仅靠排线支撑、手托或在壳内滑动；数据线应有余量，不能拉动主板。开始前轻轻移动整套头环，检查主板和摄像头没有相对晃动。联合录制时固定标定板，移动已经固定成一体的头环。软件无法仅凭图像检出或求解退出码证明安装牢固。

主板重新移动或转向后，旧 Camera–IMU 外参不再对应新安装，应固定后重录联合数据。若两个摄像头和镜头的相对位置、焦距等没有改变，主板移动本身不要求重做 Camera 标定；若摄像头也松动则需重做。静态 IMU 噪声记录是否重录取决于录制时主板是否真正静止，不能因这次主板掉落就自动宣布先前两小时数据失效。
